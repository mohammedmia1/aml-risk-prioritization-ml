How I approached the problem

01 · Prepare

Summarize synthetic transaction activity into one account-day record.

02 · Compare

Train logistic regression and XGBoost on earlier dates.

03 · Prioritize

Choose a review policy using validation data, before looking at test outcomes.

04 · Explain

Evaluate a later test period, examine SHAP explanations, and inspect drift.

Evidence & model reproducibility

Every dashboard number has an explicit source. The interactive capacity analysis uses the original exported test-account ranking; it does not run a model in your browser.

Historical export · verified

494,707 test account-days; 2,747 selected; 397 synthetic positives; ROC-AUC 0.85294841; PR-AUC 0.12311784. The test identifiers, labels and feature values match the supplied development TSV.

Fresh model · reproducible

Same chronological splits and model configuration, XGBoost 3.1.3: 389 selected positives; ROC-AUC 0.85225494; PR-AUC 0.12141259. The original and simplified configurations produced byte-identical prediction vectors in this environment.

Unresolved historical difference

536 test account-days change queue membership between historical and fresh rankings. The original fitted model artifact and historical XGBoost version are unavailable; the root cause is not established.

What this does not claim

This is a synthetic portfolio exercise, not a bank deployment. Model scores are not proven calibrated probabilities. Investigation costs are illustrative. A later monitoring population contains 922 positive labels among 923 records and cannot demonstrate ordinary production generalization.
